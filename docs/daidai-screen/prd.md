# だいだい連携画面 PRD

Issue: [miharashi-panel #17](https://github.com/ysogabe/miharashi-panel/issues/17) / 設計書: [design.md](design.md)

2026-11-08 版（レビュー反映後。設計フェーズで、実装は未着手）。「未決・要判断」は末尾と [設計書 §12](design.md#12-未決要判断) に集約している。

## 背景と目的

- 将来のゴールは双方向の連携。Echo Show や Miharashi の画面から、だいだい（Muse）を呼べるようにしたい。
- 表示側は miharashi #97「PoC: だいだい画面」で実装中（通知カード＋アバター）。
- ホスト（192.168.0.132）には local-model-lab の常駐 `llm-speech`（音声認識 Qwen3-ASR 0.6B / 日本語 TTS Irodori-TTS / Silero VAD）があり、だいだいへの橋渡し（Gadget SDK の `send-user-msg` 等）はホスト側の別 Issue が担当する。
- 本 PRD は **Panel（Android アプリ）側**の担当範囲を定める。画面構成の拡張、呼び出しの起点、音声の入口と出口、返答の表示と再生。
- 今の操作画面に呼び出し導線を足すと窮屈なため、画面を分ける（決定事項）。

## 使う人と場面

- 利用者は 1 人（家庭内）。Echo Show 5（LineageOS 18.1 / Android 11、960×480、内蔵マイクとスピーカー）を Miharashi の操作盤として常時点灯で置いている。
- 場面 1: 操作盤のそばで、画面を横にスワイプして「だいだい」に話しかける。返事が画面に出て、声でも聞こえる。
- 場面 2: だいだいからの朝の通知などが来る。利用者が近くにいそうなら、操作盤が自動でだいだい画面に切り替わって通知を見せる。部屋が真っ暗なら切り替わらず、通知はだいだい画面に溜まる。
- 場面 3: 何かの失敗（ホストが落ちている、声が拾えない）でも、普段の操作盤に戻って使い続けられる。

## ゴール / やらないこと

ゴール:
- 左右スワイプで「操作画面（A）」と「だいだい画面（B）」を行き来できる。
- B に切り替わった時点で音声入力が始まり、発話 → 返答の表示と音声再生まで 1 往復が通る。
- 通知が来たら、在席ゲートを通った場合に限り B へ自動で切り替わる。
- 在席ゲートの判定部は、画面切替の本体から分離し、将来別の在席信号に差し替えられる。
- ホスト側ブリッジ Issue の元になる「Panel が相手に要求する契約」を具体的に定める。

やらないこと（スコープ外）:
- 音声認識・音声合成そのもの（ホスト側 `llm-speech`）。
- Gadget SDK の設置・ペアリング、認識テキストのだいだいへの送信（ホスト側ブリッジ Issue）。
- Miharashi 本体のだいだい画面の表示（miharashi #97）。
- ウェイクワードによる常時待ち受け。呼び出しはスワイプによる画面切替を起点とする。
- 専用の「話す」ボタン（置かない）。
- 災害アラートとの連動（#97 のスコープ外と同じ）。

## 要求

必須:

- **R1（必須）2 画面のスワイプ切替。** 画面 A は現行の操作画面を機能・見た目とも変えない。画面 B は新設のだいだい画面（アバター、通知カード、会話の状態、返答）。左右スワイプで切り替える。操作画面のボタンのタップとは干渉しない。
- **R2（必須）待機時計との関係の整理と実装。** 待機時計は今までどおり画面 A に属する。時計からの復帰は常に画面 A。B は一定時間操作がなければ A に戻す。時計表示中でも通知による自動切替は動く。
- **R3（必須）音声入力の開始と停止。** B が表示された時点で音声入力を始める。専用ボタンは置かない。B を離れる、アプリが背面になる、操作画面の待機に入る、のいずれでも直ちに止める。マイクが開くのは B のスワイプが確定してから。マイクが実際に開いている間は画面に表示し、開始時に短い合図の音を鳴らす。通知による自動切替でマイクも開くかは設定で選べる（初期値は開く。決定は未決事項 2）。
- **R4（必須）音声の送出。** 音声は小さなチャンクで送り続ける。発話の終了判定はホスト側 VAD に委ねる。Panel 側には暴走防止の上限（マイクを開く合計時間、無音待ち、送信待ちの量、セッション全体の時間）を持ち、ホストが大きな値を返しても超えない。進行中のどの状態も有限の期限で終わる。
- **R5（必須）状態表示。** 聞き取り中／応答待ち／返答中が分かる表示にする（あわせて待機中とエラー）。アバターのポーズを状態に連動させ、miharashi #97 の `avatar_pose` と語彙を揃える。
- **R6（必須）返答の提示。** 返答テキストを B に表示し、ホスト側で生成された TTS 音声を Echo Show のスピーカーで再生する。
- **R7（必須）エラー処理。** ホスト未到達・無音・認識失敗・タイムアウト（加えてマイク権限なし・マイク使用不可・再生失敗）で、原因が分かる表示をする。B に留まるか A へ戻るかを利用者が選べ、スワイプでいつでも A に戻れる。
- **R8（必須）通知による自動切替。** だいだいから通知が来たら、在席ゲートを通った場合に限り B へ自動で切り替える。通らない通知では切り替えず、通知は B に溜まる。
- **R9（必須）在席ゲートの初期条件は照度。** 真っ暗（既存の自動消灯と同じ目安：閾値以下が 30 秒続く）なら切り替えない。明るければ利用者が近くにいる前提で切り替える。照度が取得できない端末・状況では切り替えない。
- **R10（必須）ゲートの分離。** ゲートの判定部は画面切替の本体から分離し、照度以外の信号（在席判定）への差し替え・組み合わせができる構造にする。
- **R11（必須）ゲートの設定。** 自動切替の有効／無効、暗さの閾値、暗闇の継続秒数を設定画面から調整できる。
- **R12（必須）通知到来の信号。** Miharashi の panel API の status / events（SSE）にだいだいの通知が露出している前提で、Panel は既存の購読経路から検知する。同じ通知で二度切り替えない。古い通知、アプリ起動前・背面中に来た通知、古いスナップショットの後着では切り替えない。保証する保持の範囲は「ホストが返す最新 5 件。B には最新 1 件をカードで表示し、残りは件数で示す」。
- **R13（必須）接続設定。** 既存の流儀（LAN 内の接続先 URL とトークンを設定に持つ）を踏襲し、ブリッジの接続先 URL と**ブリッジ専用のトークン**を設定に持つ。panel のトークンは流用せず、ブリッジへ送らない（キオスク操作の権限を持つため）。URL にユーザー情報・クエリは認めない。未設定なら B に案内を出し、マイクは起動しない。設定画面から接続テストできる。
- **R14（必須）既存機能を壊さない。** 画面切替・自動巡回・モニター消灯・待機時計・照度調光・暗闇消灯など、画面 A の機能は従来どおり動く。
- **R15（必須）ブリッジインターフェース要求仕様。** ホスト側ブリッジ Issue の元になる契約（音声チャンクと再送の冪等、イベントの再生、返答の受け取り、通知信号、エラー・期限）を設計書に具体的に書き、重複・順序逆転・取消・期限を含む通信シナリオ表で確認できるようにする。接続テスト用の `health` も契約に含める。
- **R16（必須）マイク権限と運用。** `RECORD_AUDIO` を宣言し、導入スクリプトで許可を付与できるようにする。録音データを端末に保存しない。自動切替が起点のマイク起動には歯止め（クールダウン、1 時間あたりの回数上限、直前が無発話なら見送り）を付ける。利用者がマイクを止める方法（マイクオフスイッチ、設定を空にする、権限の取り消し）を文書にする。

あると良い:

- **R17（あると良い）未読の手掛かり。** 溜まった通知があることを、画面 A に小さく示す。ホストが既読を管理しない場合は、B を 2 秒以上表示したら Panel が既読にする。
- **R18（あると良い）ゲート待ちの再評価。** ゲートで見送った通知を、一定時間内に明るくなったら改めて切り替える。
- **R19（あると良い）続けて話す。** 返答後に、短い待ち時間だけ再度聞き取る（連続会話）。往復回数と総時間に上限を置き、無発話なら必ず待機に戻る。初版には入れない。
- **R20（あると良い）低優先度の通知。** 通知側が低優先度と指定したものは、ゲートを通っても自動切替しない。

## 受け入れ条件

実機の項目は Echo Show 5 で確認する。単体テストの項目は JVM / Robolectric で自動確認する。

- **AC1（R1）** 実機で、A から左へスワイプすると B、B から右へスワイプすると A に移る。ボタンの上から始めたスワイプでボタンは押されず、短いタップは従来どおりボタンが押される。
- **AC2（R14）** 既存の単体テストがすべて通る。実機で、キー・メニュー・巡回の固定／再開・モニター消灯／点灯／自動・設定・待機時計・暗闇消灯が従来どおり動く。
- **AC3（R2）** 待機時計の表示中にタッチすると A に戻る（B ではない）。その操作の途中で横にドラッグしてもページは動かない。B で `daidai_idle_seconds` 無操作が続くと A に戻り（戻った瞬間に時計は出ない）、その後 `sleep_minutes` で時計に入る。B の表示中は、待機時計への遷移（`onSleepChanged(true)`）が起きない。
- **AC4（R3）** 実機で、B のスワイプが確定した時点で（ボタン操作なしに）マイクが起動し、開始音が鳴り、実際に録音している間だけ「マイク使用中」が出る。ドラッグの途中で B が半分見えている間は開かない。B を離れる、アプリが背面になる、待機に入ると、マイクが止まりセッションが取り消される。例外: 通知による自動切替でマイクを開く設定（`daidai_auto_listen`）が無効のときは、自動切替で B に入ってもマイクは開かない。
- **AC5（R4）** 単体テスト（MockWebServer）で、音声チャンクが連番・規定の形式で送られ、ホストが終了（`ended`）を返したら送信が止まる。同じ seq の再送は冪等で、終了後の再送でもエラーにならない。ホストが応答しない場合も、Panel 側の上限（マイク 45 秒、無音待ち、送信待ち 2 秒分）で打ち切る。ack が遅い（300 ms）場合も、まとめ送りで録音に追いつく。
- **AC6（R5）** 聞き取り中／応答待ち／返答中で、表示とアバターのポーズが切り替わる（状態機械の単体テストと実機の目視）。
- **AC7（R6）** 実機で、B へスワイプ → 発話 → 返答テキストの表示と TTS 音声の再生まで、1 往復が通る。
- **AC8（R7）** ホスト停止・無音・認識失敗・返答タイムアウトのそれぞれで、原因が分かる表示が出る。右スワイプで A に戻れ、A の操作が通常どおりできる。マイクは開いたままにならない。
- **AC9（R8, R9, R12）** 実機で、明るい環境でだいだいから通知を送ると B に自動で切り替わり（待機時計の表示中でも）、真っ暗な環境では切り替わらず通知が B に溜まる。「真っ暗」は閾値以下が設定秒数（既定 30 秒）続いた状態で、29 秒では切り替わり、30 秒以上では切り替わらない（単体テスト）。照度が取れない状態でも切り替わらない（単体テスト）。
- **AC10（R10）** ゲートがインターフェース越しに呼ばれ、ダミー実装へ差し替えても、画面切替の本体のコードを変えずに単体テストが通る。
- **AC11（R11）** 設定画面で自動切替の有効／無効、暗さの閾値、継続秒数を変更・保存でき、次の判定から反映される。範囲外の入力は保存されない。
- **AC12（R12）** 同じ通知 id では一度しか切り替わらない（SSE とポーリングの重複、再接続を含む）。アプリ起動前の通知と、古い通知（`age_s` が上限超え）では切り替わらない。背面や設定画面にいた間に来た通知、`rev` が古いスナップショットの後着でも切り替わらない。`daidai` を含まない旧 status でも既存動作が変わらない。
- **AC13（R13）** ブリッジ未設定のとき B に案内が出てマイクは起動しない。設定画面の接続テストで成否が分かる。
- **AC14（R16）** 導入スクリプトで `RECORD_AUDIO` が付与される。未許可のとき B に案内が出る。録音データが端末に残らない。
- **AC15（R15）** 設計書の通信シナリオ表（S1〜S15：正常、ack 喪失後の再送、終了後の新しい seq、SSE と ack の順序逆転、SSE 再接続、作成中の離脱、ホスト沈黙、不正な応答、送信詰まり など）を、Panel 側は MockWebServer の自動テストで確認でき、ホスト側の結合試験でも使える。
- **AC16（R17）** 溜まった通知がある間、A に手掛かりが出る。B を見ると消える。
- **AC17（R18）** ゲートで見送った通知が、有効期間内に明るくなると切り替わる。期間を過ぎると切り替わらない。
- **AC18（R20）** 低優先度の通知はゲートを通っても切り替わらない。（R19 は初版に入れないため、受け入れ条件は実装時に定める。）
- **AC19（R16）** 通知による自動起動のマイクは、5 分以内の再起動と 1 時間 6 回を超える起動が起きない。直前の自動起動のセッションが無発話で終わったら次の自動起動を見送る（単体テスト）。
- **AC20（R13）** ブリッジのトークンが panel のトークンと同じなら保存できない。ブリッジへの通信に panel のトークンは付かない。URL のユーザー情報・クエリは保存できない。ホストの応答に含まれるパス・別ホストの URL・リダイレクトは使われない（単体テスト）。

## 制約

- 対象端末は Android 化した Echo Show 5（LineageOS 18.1 / Android 11、960×480）。マイクとスピーカーは端末内蔵のものを使う。
- minSdk 30。実行時の追加ライブラリは今ゼロ（HTTP は `HttpURLConnection`、JSON は `org.json`）。新規依存は原則足さない。
- 音声の転送形式とブリッジのエンドポイントはホスト側 Issue が確定する。本 PRD は「チャンク送信＋ホスト側 VAD 終了判定」を想定として置く。実装着手はインターフェース確定後。
- 画面の状態は端末に保存しない（既存設計の方針）。保存するのは設定だけ。
- 通信は LAN 内の平文 http（既存と同じ）。録音を平文で流すため、安全面は設計書 §7、代替は設計書 O-11 で扱い、平文で送ってよいかは利用者が判断する。
- このホスト（lxc-t3code）では今 Android をビルドできない。実装の検証にはビルド環境の用意が前提（設計書 §9）。

## 決まっていないこと

詳細と推奨案は [設計書 §12](design.md#12-未決要判断)。要点:

1. 時計・B の無操作から戻る先（推奨: 常に画面 A）。
2. 通知で自動切替したとき、マイクも自動で起動するか（現在の既定: 起動する。歯止めを付けたうえで利用者に判断してもらう。より保守的な案は「起動しない」）。
3. 返答のあと、続けて話す方法（初版は 1 入場 1 往復。連続会話は後回し）。
4. ブリッジの転送方式（HTTP＋SSE か WebSocket か）。なお、ブリッジのトークンは panel と別にすると決定した。
5. 返答音声の形式、長い返答の扱い、返答のタイムアウト値（だいだいの応答時間の実測が要る）。
6. アバターのポーズ名の語彙とアバター画像の置き場（APK 同梱かホスト取得か）。
7. 通知側のスキーマ（`priority`、`age_s`、既読の扱い）。
8. 実機でマイク・スピーカーが LineageOS 上で使えるか（スパイクで確認）。
9. Android ビルド環境の用意の仕方。
