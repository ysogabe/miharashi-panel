# Miharashi Panel — 使い方

Android 化した Echo Show 5 にアプリを入れ、Miharashi 本体へ接続する手順です。アプリの紹介は [README](../README.md)、内部の仕組みは [技術設計](DESIGN.md) を参照してください。

## 1. 用意するもの

- Android 11（API 30）以上の端末。実機で使用しているのは Echo Show 5（LineageOS 18.1、960×480）です。
- 同じ LAN に接続した Miharashi 本体と、panel API の URL・トークン。
- ビルド用の JDK 17、Android SDK（platform 35、build-tools 35）。
- 端末へインストールするための `adb`。USB または `adb connect` で接続します。

端末の Android 化と、Miharashi 本体の導入は済んでいる前提です。

## 2. 本体側を準備する

Miharashi の `/etc/miharashi/config.toml` で panel API を有効にします。IP アドレスは本体の LAN アドレスに置き換えてください。

```toml
[panel]
enabled = true
listen = "192.168.0.132:8790"
token_file = "/etc/miharashi/panel.token"
```

トークンの作成、ファイルの権限、本体の再起動は [本体の使い方](https://github.com/ysogabe/miharashi/blob/main/docs/USAGE.md) の「操作パネルをつなぐ」を参照してください。待ち受けに `0.0.0.0` は指定できません。

モニターの消灯・点灯・自動には、本体の Home Assistant 連携とモニター制御の設定が必要です。自動巡回の固定・再開には、本体で自動巡回が有効になっていて、巡回操作の API に対応している必要があります。

## 3. ビルドする

リポジトリのルートの `local.properties` に、手元の SDK の場所を書きます。このファイルは Git の管理対象外です。

```properties
sdk.dir=/path/to/android-sdk
```

続いて実行します。

```sh
./gradlew testDebugUnitTest assembleDebug
```

debug APK は `app/build/outputs/apk/debug/app-debug.apk` に出力されます。単体テストは JVM 上で動きます。

## 4. 端末へインストールする

端末が `adb devices` に表示されることを確認してから実行します。

```sh
./scripts/install.sh
```

このスクリプトはビルド済みの debug APK をインストールし、「他のアプリの上に表示」の権限を与えて起動します。APK がなければ、先にビルドしてください。

本体の URL とトークンも一緒に設定する場合は、トークンを手元のファイルに用意して実行します。`--url` と `--token-file` は両方指定してください。この設定方法は `run-as` を使うため debug ビルド用です。

```sh
./scripts/install.sh --url http://192.168.0.132:8790 --token-file /path/to/panel.token
```

自動消灯までの分数を一緒に設定する例です。`--sleep-minutes` は URL・トークンと一緒に指定します。単独では設定されません。

```sh
./scripts/install.sh --url http://192.168.0.132:8790 --token-file /path/to/panel.token --sleep-minutes 3
```

端末の HOME アプリに指定する場合は、次を使います。インストール・起動に加え、Home を押したときにも操作盤が表示されるようになります。

```sh
./scripts/install.sh --home
```

## 5. 初期設定と接続テスト

左下の「設定」を開きます。

| 項目 | 入力する内容 |
|---|---|
| キオスクの URL | `http://192.168.0.132:8790` のような本体の URL。`/api/v1/status` は付けない |
| トークン | 本体で設定した認証用トークン。16 文字以上 |
| 触らずに操作盤を消灯するまでの分 | 0〜240 の整数。初期値は 3、0 は自動消灯しない |

「接続テスト」を押し、`OK: ホスト名 / 画面名` と表示されることを確認します。これは入力中の URL とトークンを使うテストです。設定を残すには「保存して戻る」を押してください。「戻る」だけでは入力を保存しません。

端末起動時とアプリ更新時には、自動で操作盤を前面に表示します。Android 10 以降では、起動時に前面へ出すための権限、または HOME アプリの指定が必要です。`install.sh` は必要な権限を設定し、`--home` は HOME も指定します。スワイプだけのロック画面より手前に表示しますが、PIN などの解除は利用者が行います。

## 6. 日常の操作

| 場所 | 操作 |
|---|---|
| 中央下の前・決定・次 | 前後の画面へ移動。決定は表示中の画面によって意味が変わる |
| 右側の上・下 | 写真の前後移動など、表示中の画面内の操作 |
| 右下のメニュー | 画面の一覧を開閉。項目をタップすると、その画面へ直接移動 |
| 中央上の現在画面のカード | 自動巡回を止めて固定。固定中にもう一度タップすると、次の画面へ進んで巡回を再開 |
| 左側の消灯・点灯・自動 | 本体につながったモニターの設定を変更。操作盤自身の消灯とは別 |

ボタンの説明は本体から受け取ったものを表示します。使えない操作は灰色になります。古い本体が説明を返さない場合は、汎用の説明になります。

本体の自動巡回には、次の状態があります。

| 状態 | 意味 |
|---|---|
| 自動巡回中 | 本体の設定に従って画面を切り替えている |
| 巡回停止中・再開までの残り時間 | キー操作や画面選択による一時停止。最後の操作から設定された時間がたつと再開 |
| この画面で固定中 | 巡回を止めたままの状態。時間がたっても再開せず、キー操作や画面選択でも解除されない |

固定は巡回を止める操作なので、その後も手動で別の画面へ移動できます。本体を再起動すると固定は解除され、本体の設定どおりの巡回に戻ります。本体で巡回が無効なら巡回の表示は出ません。巡回操作に未対応の本体では、状態を見るだけでカードは押せません。

操作が本体に受け付けられると、音と振動で知らせます。失敗するとボタンが赤く点滅し、自動では再送しません。

操作盤に設定した時間だけ触れないと、画面を黒くしてバックライトを最小にします。最初のタッチで元の明るさに戻り、そのタッチでは本体へ操作を送りません。夜間の時刻に応じた減光機能はありません。

確認するときは、画面の前後移動、メニューからの選択、固定、再開の順に操作し、本体の画面と操作盤の表示が追従するかを見ます。モニター制御を設定している場合は、消灯・点灯・自動も確認してください。

## 7. 接続できないとき

| 表示・症状 | 確認すること |
|---|---|
| 未設定 | URL とトークンを入力し、「保存して戻る」を押したか |
| ホストが見つからない／接続できない | URL、本体の起動、同じ LAN への接続、panel API の待ち受け設定 |
| HTTP 401 | トークンが本体と一致しているか |
| 応答がない | 本体と LAN の通信状態。アプリは再接続を試みる |
| STALE／OFFLINE | 最後に状態を取得してから時間がたっている。5 秒を超えると STALE、15 秒を超えると OFFLINE |
| モニターのボタンが灰色 | 本体がモニター制御に対応し、Home Assistant 連携が設定されているか |
| 巡回を固定できない | 本体の自動巡回が有効か、`rotation.control` を返す API に対応しているか |
| 再起動後に操作盤が出ない | 起動用の権限または HOME の指定。必要なら `install.sh` で入れ直す |

OFFLINE でも最後に取得した状態は薄く表示します。最新の状態とは限りません。ヘッダーの `WIFI` は端末の Wi-Fi 接続、`API` は本体からの状態取得を表し、別々の状態です。
