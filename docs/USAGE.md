# Miharashi Panel — 使い方

Android 化した Echo Show 5 にアプリを入れ、Miharashi 本体へ接続する手順です。アプリの紹介は [README](../README.md)、内部の仕組みは [技術設計](DESIGN.md) を参照してください。

## 1. 用意するもの

- Android 11（API 30）以上の端末。実機で使用しているのは Echo Show 5（LineageOS 18.1、960×480）です。
- 同じ LAN に接続した Miharashi 本体と、panel API の URL・トークン。
- ビルド用の JDK 17、Android SDK（platform 35、build-tools 35）。
- 端末へインストールするための `adb`。USB または `adb connect` で接続します。

端末の Android 化と、Miharashi 本体の導入は済んでいる前提です。

## 2. 本体側を準備する

Miharashi の `/etc/miharashi/config.toml` で panel API を有効にします。IP アドレスは本体の LAN アドレスに置き換えてください。

```toml
[panel]
enabled = true
listen = "192.168.0.132:8790"
token_file = "/etc/miharashi/panel.token"
```

トークンの作成、ファイルの権限、本体の再起動は [本体の使い方](https://github.com/ysogabe/miharashi/blob/main/docs/USAGE.md) の「操作パネルをつなぐ」を参照してください。待ち受けに `0.0.0.0` は指定できません。

モニターの消灯・点灯・自動には、本体の Home Assistant 連携とモニター制御の設定が必要です。自動巡回の固定・再開には、本体で自動巡回が有効になっていて、巡回操作の API に対応している必要があります。

## 3. ビルドする

リポジトリのルートの `local.properties` に、手元の SDK の場所を書きます。このファイルは Git の管理対象外です。

```properties
sdk.dir=/path/to/android-sdk
```

続いて実行します。

```sh
./gradlew testDebugUnitTest assembleDebug
```

debug APK は `app/build/outputs/apk/debug/app-debug.apk` に出力されます。単体テストは JVM 上で動きます。

## 4. 端末へインストールする

端末が `adb devices` に表示されることを確認してから実行します。

```sh
./scripts/install.sh
```

このスクリプトはビルド済みの debug APK をインストールし、「他のアプリの上に表示」と、だいだい連携画面用のマイクの権限(`RECORD_AUDIO`)を与えて起動します。APK がなければ、先にビルドしてください。だいだい連携の接続先やトークンの設定、マイクの権限、止め方は [8. だいだい連携画面](#8-だいだい連携画面音声) にまとめています。

本体の URL とトークンも一緒に設定する場合は、トークンを手元のファイルに用意して実行します。この設定方法は `run-as` を使うため debug ビルド用です。設定は**指定した項目だけ**を差し替え、端末にある既存の設定(指定しなかった `url`、`token`、`sleep_minutes`、`daidai_*` など)は消えません。`--url` と `--token-file` は、片方だけでも指定できます。

```sh
./scripts/install.sh --url http://192.168.0.132:8790 --token-file /path/to/panel.token
```

時計表示までの分数を設定する例です。`--sleep-minutes` は単独でも指定できます(ほかの設定は残ります)。

```sh
./scripts/install.sh --url http://192.168.0.132:8790 --token-file /path/to/panel.token --sleep-minutes 3
```

端末の HOME アプリに指定する場合は、次を使います。インストール・起動に加え、Home を押したときにも操作盤が表示されるようになります。

```sh
./scripts/install.sh --home
```

## 5. 初期設定と接続テスト

左下の「設定」を開きます。

| 項目 | 入力する内容 |
|---|---|
| キオスクの URL | `http://192.168.0.132:8790` のような本体の URL。`/api/v1/status` は付けない |
| トークン | 本体で設定した認証用トークン。16 文字以上 |
| 時計表示までの分 | 0〜240 の整数。初期値は 3、0 は無効 |
| 照度に合わせてShow 5の明るさを調整 | 初期値は有効。通常の操作盤を照度に応じて5〜100%に調整 |
| 真っ暗な状態が30秒続いたらmiharashiを消灯 | 初期値は有効。本体が「自動」の場合だけ動作 |
| 暗闇とみなす照度 | 0〜100 lx、初期値は1 lx以下。30秒続いたら消灯判定 |

設定画面には照度センサー名と現在の照度（lx）を表示します。未搭載・読み取り不可の端末では従来の明るさで動き、照度による本体消灯は行いません。「値を待機中」の間も、有効な初回値を受け取るまではシステムの明るさを使い、自動消灯を始めません。ROMによっては、照度が変わるまで初回値が届かない場合があります。設定画面自身は読みやすさを保つためシステムの明るさを使います。

だいだい連携の項目は、設定画面の「── だいだい連携 ──」の節にあります。[8. だいだい連携画面](#8-だいだい連携画面音声) を参照してください。

「接続テスト」を押し、`OK: ホスト名 / 画面名` と表示されることを確認します。これは入力中の URL とトークンを使うテストです。設定を残すには「保存して戻る」を押してください。「戻る」だけでは入力を保存しません。

端末起動時とアプリ更新時には、自動で操作盤を前面に表示します。Android 10 以降では、起動時に前面へ出すための権限、または HOME アプリの指定が必要です。`install.sh` は必要な権限を設定し、`--home` は HOME も指定します。スワイプだけのロック画面より手前に表示しますが、PIN などの解除は利用者が行います。

## 6. 日常の操作

| 場所 | 操作 |
|---|---|
| 中央下の前・決定・次 | 前後の画面へ移動。決定は表示中の画面によって意味が変わる |
| 右側の上・下 | 写真の前後移動など、表示中の画面内の操作 |
| 右下のメニュー | 画面の一覧を開閉。項目をタップすると、その画面へ直接移動 |
| 中央上の現在画面のカード | 自動巡回を止めて固定。固定中にもう一度タップすると、次の画面へ進んで巡回を再開 |
| 左側の消灯・点灯・自動 | 本体につながったモニターの設定を変更。操作盤自身の消灯とは別 |
| 画面を左へスワイプ | だいだい連携画面(B)へ。右へスワイプすると操作盤に戻る。ヘッダーの「だいだい N」は、見ていないだいだいの通知があること(B を見ると消える) |

ボタンの説明は本体から受け取ったものを表示します。使えない操作は灰色になります。古い本体が説明を返さない場合は、汎用の説明になります。

本体の自動巡回には、次の状態があります。

| 状態 | 意味 |
|---|---|
| 自動巡回中 | 本体の設定に従って画面を切り替えている |
| 巡回停止中・再開までの残り時間 | キー操作や画面選択による一時停止。最後の操作から設定された時間がたつと再開 |
| この画面で固定中 | 巡回を止めたままの状態。時間がたっても再開せず、キー操作や画面選択でも解除されない |

固定は巡回を止める操作なので、その後も手動で別の画面へ移動できます。本体を再起動すると固定は解除され、本体の設定どおりの巡回に戻ります。本体で巡回が無効なら巡回の表示は出ません。巡回操作に未対応の本体では、状態を見るだけでカードは押せません。

操作が本体に受け付けられると、音と振動で知らせます。失敗するとボタンが赤く点滅し、自動では再送しません。

操作盤に設定した時間だけ触れないと、フリップ時計を表示します。時計は端末の現地時刻を24時間制で表示し、待機中も前面にいる間は本体の状態同期を続けます。どこかをタッチすると操作盤へ戻り、復帰に使ったタッチでは本体へ操作を送りません。待機中も自動調光が有効で照度が取得できれば5〜100%で調整し、それ以外は5%にします。実際の明るさは端末によって異なります。夜間の時刻に応じた減光機能はありません。画面案と待機時の動作は[無操作時のフリップ時計](IDLE_CLOCK.md)を参照してください。

### 照度による調光と暗闇での消灯

操作盤・時計とも照度0 lxで5%、500 lx以上で100%となる対数曲線で明るさを調整します。小さな値の揺れでは明るさを書き換えず、時計にも同じ曲線を適用します。自動調光を無効にすると、通常の操作盤ではシステムの明るさ、待機時計では従来どおり5%になります。Android全体の明るさ設定や他のアプリは変更しません。

暗闇での消灯は、本体モニターが「自動」で点灯中、モニター操作に対応し、5秒以内にエラーなく状態を取得できた場合だけ動きます。1 lx以下（変更可能）が30秒続いたら、一度だけ消灯を送ります。一瞬手でセンサーを覆っただけでは消灯しません。時計表示中も前面にいる間は判定します。

**手動の「点灯」「消灯」を優先**します。操作盤で「点灯」「消灯」「自動」を押した直後は、一度明るくなるまで暗闇の自動消灯を抑止します。再判定には5 lx以上、または設定した暗闇の照度＋4 lx以上のうち大きい方が必要です。

**明るくなっても自動点灯はしません。** 消灯後は本体のモードが「消灯」になります。再点灯は操作盤の「点灯」か「自動」で行ってください。失敗するとメッセージを表示し、同じ暗闇では再送しません。本体が未設定・オフライン・手動モードの場合は自動消灯を送りません。

設定画面で現在の照度を確認し、センサーを手で覆ったときに値が変わるかを見ます。真っ暗な部屋の測定値をもとに閾値を調整してください。ROM・センサー位置・画面の反射によって照度は異なります。

2026年10月27日、USB接続した使用中のEcho Show 5（checkers、LineageOS 18.1、2026年6月24日ビルド）にAPKを上書き適用して確認しました。遮光で照度が30〜31 lxから0〜1 lxへ変化し、バックライトが約58%から5%へ下がり、遮光解除後に約58%へ戻ることを確認しました。本体の消灯経路は暗闇の閾値を一時的に40 lxへ上げ、実測29〜30 lxが30秒続いた後に「消灯中」へ変わることで確認しています。試験後は閾値を1 lxへ戻しています。通常の1 lx設定で真っ暗な部屋から本体が消灯するまでの一連の試験と、長時間運用は別途確認が必要です。

確認するときは、画面の前後移動、メニューからの選択、固定、再開の順に操作し、本体の画面と操作盤の表示が追従するかを見ます。モニター制御を設定している場合は、消灯・点灯・自動も確認してください。

## 7. 接続できないとき

| 表示・症状 | 確認すること |
|---|---|
| 未設定 | URL とトークンを入力し、「保存して戻る」を押したか |
| ホストが見つからない／接続できない | URL、本体の起動、同じ LAN への接続、panel API の待ち受け設定 |
| HTTP 401 | トークンが本体と一致しているか |
| 応答がない | 本体と LAN の通信状態。アプリは再接続を試みる |
| STALE／OFFLINE | 最後に状態を取得してから時間がたっている。5 秒を超えると STALE、15 秒を超えると OFFLINE |
| モニターのボタンが灰色 | 本体がモニター制御に対応し、Home Assistant 連携が設定されているか |
| 巡回を固定できない | 本体の自動巡回が有効か、`rotation.control` を返す API に対応しているか |
| 再起動後に操作盤が出ない | 起動用の権限または HOME の指定。必要なら `install.sh` で入れ直す |

OFFLINE でも最後に取得した状態は薄く表示します。最新の状態とは限りません。ヘッダーの `WIFI` は端末の Wi-Fi 接続、`API` は本体からの状態取得を表し、別々の状態です。

自動調光が有効な場合、10 lx以下は従来の配色、250 lx以上は最大コントラストとし、その間は滑らかに補間します。背景を黒へ、文字と時計の数字・コロンを白へ近づけ、操作可能なボタンと選択行の枠を強調します。状態色と無効ボタンの区別は維持します。時計の濃淡変動はコントラストに応じて抑え、最大時は減光しません。位置の移動とフリップは継続します。今回の明るい場所での表示改善は実機未確認です。既載の実機試験は変更前の記録です。

## 8. だいだい連携画面(音声)

操作盤の隣に、だいだい(音声アシスタント)の通知を見て、話しかけられる画面 B があります。ここでは、音声まわりの準備、止め方、自動で切り替わる条件を説明します。内部の仕組みは [技術設計の §9](DESIGN.md#9-だいだい連携画面)、設計の詳細は [だいだい連携画面の設計](daidai-screen/design.md) です。

> **現状:** 話しかけた音声を受けて返事を作る**ホスト側のブリッジ(local-model-lab 側、別 Issue)は未実装**です。Miharashi 本体の `daidai` ブロック(通知)も未実装です。Panel 側は、設計書の契約どおりに振る舞う偽の相手と MockWebServer で自動テストしただけで、**実物のブリッジとの接続、実機(Echo Show 5)でのマイク・スピーカー・照度センサー・スワイプの感触は未確認**です。ブリッジの要求仕様は [設計書 §5.2](daidai-screen/design.md) にあります。
>
> ブリッジや `daidai` ブロックがなくても、操作盤(A)の機能は従来どおり動きます。

### 8.1 画面の使い方

- 操作盤を**左へスワイプ**すると B、**右へスワイプ**すると操作盤に戻ります。ボタンの上から始めたスワイプでボタンは押されません。短いタップは従来どおりです。
- B には、アバター(初版は仮の図形)、最新の通知 1 件と「他 N 件」、状態(待機中・聞き取り中・応答待ち・返答中・エラー)、聞き取った言葉、返答が出ます。通知がなければ「話しかけてください」と出ます。
- ブリッジが設定済みなら、B に入る(スワイプが落ち着く)と短い開始音が鳴り、マイクが開きます。マイクが開いている間は、B のヘッダーに「● マイク使用中」が出ます。話しかけると、ブリッジが聞き取ってだいだいに渡し、返答のテキストと音声が返ります。
- B で `daidai_idle_seconds`(初期値 60 秒、10〜600)の間、触らず会話もしていないと操作盤に戻ります。会話の最中は戻りません。
- 設定画面を開く・アプリが背面になる・待機時計に入る・モニターが消灯するときは、マイクを必ず止めます。再び前面になったときは必ず操作盤から始まり、自動ではマイクを開きません。
- ブリッジが未設定のときは、B にその旨と設定の手順が出ます。マイクの権限がないときは、許可のコマンドが出ます。

### 8.2 準備

**1. ホスト側のブリッジ。** 上の現状のとおり未実装です。接続先は `http://192.168.0.132:8800` のような URL で、設定画面の「ブリッジの URL」に入れます。

**2. ブリッジ専用のトークン。** ブリッジの認証用に、**panel のトークンとは別の値**を用意します。可視 ASCII(空白・日本語は不可。`install.sh` はさらに XML の特殊文字 `" < > & '` も不可)で **16 文字以上**です。panel のトークンはキオスクを操作する権限を持つため、ブリッジには渡しません。同じ値は設定画面でも `install.sh` でも拒否されます。32 バイト程度の乱数を勧めます。

```sh
openssl rand -hex 24 > daidai.token
```

**3. マイクの権限。** `install.sh` が `RECORD_AUDIO` を付与します(権限ダイアログは出ません)。付与に失敗しても導入は続き、警告が出ます。手動で付与するには次を実行します。

```sh
adb shell pm grant io.github.ysogabe.miharashi.panel android.permission.RECORD_AUDIO
```

権限がないまま B を開くと、「マイクの権限がありません」と出て、このコマンドを案内します。

**4. 接続先とトークンを入れる。** 次のどちらかです。

- 設定画面の「── だいだい連携 ──」の節で入力し、「保存して戻る」を押す。
- `install.sh` で書き込む(debug ビルド用。`run-as` を使います)。

```sh
./scripts/install.sh --daidai-url http://192.168.0.132:8800 --daidai-token-file daidai.token
```

| オプション | 内容 |
|---|---|
| `--daidai-url URL` | ブリッジの接続先。`http://` か `https://`。ホストは英数字と `. _ -`(または IPv6 の `[...]`)、ポートは省略か 1〜65535 の数字だけ。ユーザー情報(`@`)・クエリ・フラグメント・空白は不可(設定画面と同じ規則) |
| `--daidai-token-file FILE` | ブリッジ専用トークンを書いたファイル。トークンはコマンド行に出さず、標準入力で端末へ渡す |
| `--dry-run` | 実行する `adb` のコマンドと、書き込む設定の内容(トークンは `***`)を表示するだけ。端末には何もしない |

`install.sh` は、**指定した項目だけを差し替え**ます。端末の `shared_prefs/panel.xml` を先に読み、指定していない既存の設定(`url`、`token`、`sleep_minutes`、`daidai_*` など)はそのまま残します。たとえば `--daidai-url` だけを指定しても、ほかの設定は消えません。端末の設定を読めないとき、ファイルが途中で切れているように見えるときは、書き込まずに終わります。書き込みは一時ファイルに行い、行数と末尾を確かめてから置き換えるので、途中で切断されても既存の設定は壊れません。

まず `--dry-run` を付けて、内容を確かめることを勧めます。

```sh
./scripts/install.sh --dry-run --daidai-url http://192.168.0.132:8800 --daidai-token-file daidai.token
```

**5. 設定画面の「── だいだい連携 ──」の節。**

| 項目 | 内容 |
|---|---|
| ブリッジの URL | 空にすると音声機能が完全に止まる(`daidai_url`) |
| ブリッジ専用のトークン | 16 文字以上の可視 ASCII。panel のトークンと別の値(`daidai_token`) |
| ブリッジの接続テスト | `GET /v1/health` を、ブリッジ専用のトークンだけで呼ぶ。`OK: ブリッジに接続できた`(音声認識・音声合成・だいだいのうち準備できていないものがあれば、その名前も出る)、`NG: 認証に失敗`、`NG: ブリッジに接続できない`、`NG: 応答が正しくない`のいずれか。入力中の値を使うテストで、保存は「保存して戻る」 |
| だいだいの通知で自動的にだいだい画面へ切り替える | 初期値は有効(`daidai_auto_switch`) |
| 暗さの閾値 | 0〜100 lx、初期値 1 lx。これ以下を暗闇とみなす(`daidai_gate_dark_lux`) |
| 暗闇の継続秒数 | 0〜600 秒、初期値 30 秒。暗闇がこの秒数続いたら自動で切り替えない(`daidai_gate_dark_seconds`) |
| 自動で切り替えたときも話を聞く(マイクを開く) | 初期値は有効(`daidai_auto_listen`) |
| だいだい画面の無操作秒数 | 10〜600 秒、初期値 60 秒。過ぎると操作盤へ戻る(`daidai_idle_seconds`) |

節の最後に「直近の自動切替の判定」が 1 行出ます。切り替わらなかったとき、理由(暗闇・照度不明・操作中・低優先度など)を確かめられます。

**6. 音量。** アプリには音量の設定がありません。

- 返答の再生は端末の**メディア音量**に従います。足りないときは端末側で上げます。
- マイクを開くときの開始音は、アプリが決めた控えめな音量(`ToneGenerator` の音量 30、範囲は 0〜100)で鳴ります。これもメディア音量に従います。
- マイクの感度(ゲイン)の設定もありません。`VOICE_RECOGNITION` で録音し、使えない端末では `MIC` を使います。

スピーカーの音量が足りるか、LineageOS 18.1 の Echo Show 5 でマイクとスピーカーが使えるか、開始音と録音が重ならないかは、**実機で未確認**です。

### 8.3 マイクの止め方

マイクが開くのは、ブリッジが設定済みで、B が確定して表示されているときだけです。常時待ち受けはしません。次の方法で止められます。

1. **本体のマイクオフスイッチ(一次手段)。** Echo Show 5 のハードウェアのスイッチを切ると、マイクからの音が完全に 0 になる想定です。Panel は録音を始めて 3 秒間がすべて無音(RMS が 2.0 以下)のとき、これを「マイクオフスイッチの疑い」として検出し、「マイクから音が来ません。本体のマイクオフスイッチを確認してください」と案内します。スイッチ自体がマイクを物理的に切るかは、実機で未確認です。
2. **設定の `daidai_url` を空にする。** 音声機能が完全に止まります(B は未設定の案内を出し、セッションもマイクも作りません)。設定画面で空にして保存するか、次のコマンドを実行します。

   ```sh
   ./scripts/install.sh --daidai-url ''
   ```

3. **権限を取り上げる。**

   ```sh
   adb shell pm revoke io.github.ysogabe.miharashi.panel android.permission.RECORD_AUDIO
   ```

   以後、B は権限がない旨を案内し、マイクを開きません。`install.sh` を再実行すると、再び付与されます。

### 8.4 導入後のネットワーク ADB

`adb connect` でネットワーク越しに導入した場合は、**使い終わったらネットワーク ADB を無効にして**ください。常時有効のままだと、LAN 上の機器が端末を操作できる状態が続きます。有効にしておく場合は、adb の RSA 認証(接続を許可するか尋ねる確認)を有効のままにしてください。`install.sh` の設定の書き込みは `run-as`(debug ビルド)を使うので、長く運用するなら release ビルドでの設定の入れ方を別途検討してください。

### 8.5 通信は平文です

Panel と本体、Panel とブリッジの通信は、既存の本体との通信と同じく平文の http です。**録音した音声とブリッジ専用トークンが、LAN の中を暗号化されずに流れます。** 通知の真正性も、平文のままでは保証できません(LAN 上の別の機器が偽の通知を出せる可能性があります)。LAN を信頼できる環境で使うこと、ブリッジを LAN 側のインターフェースだけで待ち受けて端末の IP だけを許可することを勧めます。TLS にするか、この前提で使うかは利用者が判断してください([設計書 §7](daidai-screen/design.md) と O-11)。

Panel 側では、音声・認識結果・返答・通知を端末に保存せず(ファイルに書かない)、トークンや本文を logcat に出しません。

### 8.6 通知で自動的に B に切り替わる条件

本体から新しい通知が届くと、次の条件がすべて満たされたときに自動で B へ切り替わります。

- 設定の「だいだいの通知で自動的に〜」が有効(`daidai_auto_switch`)。
- **起動後に新しく届いた通知**であること。アプリを前面にしたあと(設定画面から戻った場合を含む)に最初に受け取った状態に含まれる通知では切り替えません。背面にいた間や、起動前の通知は、未読として残るだけです。
- 優先度が `low` でなく、通知から **30 秒以内**であること。
- すでに B にいない(B にいるときはカードを更新するだけ)。
- 利用者がスワイプ中・アニメーション中でない。操作中なら、落ち着いてから**一度だけ**判定し直します。
- **照度ゲート**が「人がいる」と判断すること。照度が暗闇の閾値(`daidai_gate_dark_lux`、初期値 1 lx)以下の状態が `daidai_gate_dark_seconds`(初期値 30 秒)以上続いていれば見送ります。照度センサーがない、登録に失敗した、前面になってから最初の値がまだ届いていない、のときも見送ります(安全側)。照度は在席の推定にすぎず、安全装置ではありません。

待機時計の最中でも、条件を満たせば時計を解除して B へ切り替えます。見送った通知は取っておかず、あとで同じ通知で切り替わることはありません(B の通知カードとヘッダーの未読の表示には残ります)。

### 8.7 自動切替でマイクが開く条件と歯止め

自動切替で B に入ったとき、マイクを開くのは、次の歯止めをすべて通ったときだけです。切り替え自体は歯止めがあっても行われ、その場合は通知を見るだけでマイクは開きません。スワイプで入ったときは、これらの歯止めは関係なくマイクが開きます(ブリッジが設定済みの場合)。

- 設定の「自動で切り替えたときも話を聞く」(`daidai_auto_listen`)が有効。**初期値は有効**です(設計書 O-2 で決定済み)。無効にすれば、自動切替ではマイクを開きません。
- 直前の自動のマイク起動から **5 分**以上たっている(クールダウン)。
- 直近 **1 時間**の自動のマイク起動が **6 回**未満。
- 直前の自動のマイク起動が「無発話」(`no_speech`)で終わっていたら、見送ります。誰もいない部屋で通知のたびに聞き続けないためです。時間では解除されず、利用者がスワイプで B を開いて、無発話以外で会話が終わると解除されます。アプリの画面を作り直しても(メモリのみなので)解除されます。

マイクを開くときは短い開始音が鳴り、B のヘッダーに「● マイク使用中」が出ます。1 回に録音する時間は最大 45 秒、1 回の会話は最大 120 秒で、ブリッジの値でこれを超えることはありません。

### 8.8 未読の手掛かり

見ていないだいだいの通知があるとき、操作盤のヘッダー(WIFI の表示と時刻のあいだ)に小さく「だいだい N」と出ます(10 件以上は「だいだい 9+」)。待機時計の間は出ません。タップしても何も起きません。スワイプで B を見ると消えます。

- B が確定して **2 秒以上**表示されたら、その時点の通知をすべて既読にします。2 秒たたずに離れたら既読にしません。新しい通知が来れば、また出ます。既読の状態は端末に保存せず、アプリを閉じると忘れます。
- ホストが既読を管理する場合(status の `daidai.ack` が `true`)は、ホストが数えた未読件数を表示し、既読にしたときに最新の通知の id をホストへ伝えます。

### 8.9 既知の制限

- 初版は **1 回の入場につき 1 往復**です。続けて質問するには、いったん A に戻って B に入り直します(連続した会話はありません)。
- アバターは**仮の図形**です。本物の絵は別途用意します。
- ホストのブリッジが未実装のため、実物との接続は未確認です。
- 実機で未確認のもの: マイクとスピーカーの動作と音量、開始音と録音の重なり、マイクオフスイッチの検出、照度センサーの初回の値(ROM によっては変化するまで届かない場合があります)、スワイプの感触とシステムのジェスチャとの競合、時計中の切り替えとバックライト、未読チップの見た目。
