# Miharashi Panel — 技術設計

v0.2.0 のアプリ実装を説明します。導入と操作は [使い方](USAGE.md)、文書の一覧は [Docs](README.md) を参照してください。

## 1. 本体とアプリの役割

Miharashi 本体が、画面の切り替え、メニュー、自動巡回、モニター制御の状態を管理します。アプリは操作を送信し、本体から取得した状態を表示します。表示中の画面をアプリ独自の判断で切り替えたり、Home Assistant を直接操作したりはしません。

取得した状態と通信エラーはメモリ上に保持します。端末に保存するのは URL、トークン、待機時計表示までの分数です。画面や巡回の状態は保存せず、再接続時に本体から取得します。

サーバー側の正式な API 仕様は [miharashi の操作パネル設計 §5.2](https://github.com/ysogabe/miharashi/blob/main/docs/panel/DESIGN.md) で管理します。この文書では、アプリがその API をどう使うかを説明します。

## 2. アプリの構成

| 部品 | 役割 |
|---|---|
| `PanelActivity` | 全画面、横向き表示、明るさの変更。`onResume` で同期を始め、`onPause` で停止 |
| `PanelView` | Canvas での描画、タップ、操作結果のフィードバック、巡回の残り時間の表示 |
| `PanelLayout` | 960×480 を基準とする配置とタップ領域。表示領域に合わせて比率を保って拡大・縮小 |
| `PanelState` / `KioskStatus` | 本体から取得した状態、最後の取得時刻、エラー、情報の鮮度を保持 |
| `KioskClient` | 状態の取得、SSE の受信、キー・画面選択・モニター・巡回操作の送信 |
| `KioskSync` | 定期取得と SSE の再接続、操作の順次送信、UI スレッドへの結果通知 |
| `IdleTimer` | 最後の操作からの経過時間に基づく待機時計への移行判定 |
| `FlipClock` の各クラス | 現地時刻、フリップ状態、動きと濃淡、安全な配置、低頻度の更新間隔を計算 |
| `Settings` / `SettingsActivity` | SharedPreferences への設定保存と、入力・接続テストの画面 |
| `BootReceiver` | 端末の起動時とアプリの更新時に `PanelActivity` を起動 |

Kotlin と Android 標準の View / Canvas を使います。HTTP は `HttpURLConnection`、JSON は Android の `org.json` で処理します。Kotlin 標準ライブラリ以外に、実行時の追加ライブラリはありません。テスト用の依存は別にあります。

## 3. 状態の同期

同期は Activity が前面にある間だけ動きます。

1. 同期開始時に `GET /api/v1/status` で状態を取得します。その後も取得処理の終了から 5 秒の間隔で読み直します。
2. 並行して `GET /api/v1/events` に接続し、SSE の `status` イベントを受け取ります。
3. どちらから届いた状態も UI スレッドで `PanelState` に反映します。
4. SSE が切れたら 1、2、4…最大 30 秒の間隔で再接続します。状態を受信すると再接続間隔を初期値に戻します。

通常の接続タイムアウトは 3 秒、読み取りタイムアウトは 5 秒です。SSE の読み取りタイムアウトは 40 秒です。SSE のコメント行は無視し、複数の `data` 行はまとめて処理します。

設定画面から同じ接続先へ戻る場合は、前回の状態を引き継いで同期を再開します。URL またはトークンが変わった場合は、前の本体の状態を破棄します。同期停止後に届いた結果は画面へ反映しません。

### 鮮度と巡回の残り時間

| 最後に状態を取得してからの時間 | ヘッダー |
|---|---|
| 5 秒以内 | `API`、緑 |
| 5 秒超〜15 秒以内 | `STALE`、黄 |
| 15 秒超、または未取得 | `OFFLINE`、赤 |

時刻の計算には端末の経過時間を使います。エラーが起きても最後の状態は残し、OFFLINE では薄く表示します。

一時停止中の巡回は、受け取った `resume_in_s` から受信後の経過時間を引き、画面上で残り時間を更新します。表示上の残りが 0 になっただけでは巡回再開を確定せず、本体から取得した状態に従います。

## 4. 操作の送信

| 操作 | 送信先 | JSON の項目 |
|---|---|---|
| キー操作 | `POST /api/v1/input` | `key`: `prev` / `next` / `select` / `up` / `down` / `menu` |
| メニューから画面を選ぶ | `POST /api/v1/screen` | `id`: 本体が返した画面 ID |
| モニターの設定を変える | `POST /api/v1/display` | `mode`: `auto` / `force_on` / `force_off` |
| 自動巡回を止める・再開する | `POST /api/v1/rotation` | `mode`: `off` / `on` |

API のリクエストには Bearer トークンを付けます。送信は専用の単一スレッドで順番に処理し、`204` を成功とします。成功時はフィードバックを返し、SSE を待たずに `/status` を読み直します。受け付けられた操作の最終的な結果は、取得した状態から表示します。

失敗するとボタンを赤く点滅させ、エラーを表示します。二重操作を避けるため自動再送はしません。HTTP エラーではコードと、本体が返したエラーの説明を使います。

モニターの操作では、本体が Home Assistant の設定を変更します。アプリはその後に取得した `display` を表示します。通信中や情報が古いときも「常に一致する」とは扱いません。

## 5. 表示と操作領域

- 左側: モニターの状態、消灯・点灯・自動、設定。
- 中央上: 現在の画面名と詳細、巡回の状態。巡回操作が可能ならカード全体が固定・再開のボタンになる。
- 中央下: 前の画面・決定・次の画面に対応するボタン。
- 右側: 上・下・メニューに対応するボタン。
- ヘッダー: 本体名、API の鮮度、Wi-Fi の接続状態、時刻。

実際のボタンの説明は `keys` で受け取ります。値が `null` のキーは灰色にして操作を送りません。キーのアイコンは端末のフォントに依存しない図形で描きます。

メニューを開いている間は、現在画面のカードの代わりに画面一覧を出します。一度に表示するのは最大 5 行で、選択中の項目が見える範囲を表示します。行をタップすると、その ID を `/screen` に送ります。

巡回を固定しているときは、中央のカードを青い面と枠にし、「固定」と表示します。固定中でも手動の画面選択は可能です。固定の解除と再開時の遷移は本体が管理します。

## 6. 起動と待機時計

`BOOT_COMPLETED` と `MY_PACKAGE_REPLACED` を受け取ってアプリを起動します。端末の HOME アプリとしても指定できます。起動に必要な権限と導入方法は [使い方](USAGE.md) にまとめています。

表示は横向きの全画面で、システムバーを隠します。端からスワイプすると一時的にバーを表示できます。

無操作時は低輝度の大きなフリップ時計を表示します。初期値 3 分、設定画面では 0〜240 分を指定でき、0 は無効です。最初のタッチは復帰にだけ使い、本体への操作は送りません。設定画面から戻ったときも無操作時間を数え直します。承認済みの画面画像、画面遷移、残像対策と実装仕様は [無操作時のフリップ時計](IDLE_CLOCK.md) に保存しています。

夜間の時刻に応じた減光は実装せず、無操作時の待機時計で減光します。従来の自動消灯に関する方針は [本体側の設計 §7](https://github.com/ysogabe/miharashi/blob/main/docs/panel/DESIGN.md) に記録されています。

## 7. 旧 API との互換性

| 本体の応答 | アプリの扱い |
|---|---|
| `keys` がない | 汎用のボタン説明を表示 |
| `display` がない、または `display.control` が false | モニター操作を無効化 |
| `rotation` がない、または未知の巡回状態 | 巡回の表示を出さない |
| `rotation.control` がない、または false | 巡回の状態を見るだけで固定・再開はできない |
| `menu` がない、または指定された画面が見つからない | メニューを閉じているものとして扱う |

対応する schema は 1 です。より新しい schema 番号でも、知っている項目を読みます。必須項目の構造が変わった場合まで互換性を保証するものではありません。

## 8. テストと確認

```sh
./gradlew testDebugUnitTest assembleDebug
```

| 対象 | 確認する内容 |
|---|---|
| `PanelStateTest` | 状態 JSON の読み取り、鮮度、巡回の残り時間、互換性 |
| `KioskClientTest` | MockWebServer に対する API 通信、エラー、SSE の処理 |
| `PanelLayoutTest` | 配置とタップ領域 |
| `IdleTimerTest` | 無操作時間、待機時計への移行と復帰 |
| `FlipClockTest` | 分・日の境界、時刻補正、フリップの進行、移動範囲、分の境目の更新予約 |

JSON の例は [テスト用フィクスチャ](../app/src/test/resources/fixtures/) にあります。API の項目を変えるときは、本体の仕様とアプリの読み取り処理に加え、対応するフィクスチャも見直します。

単体テストでの確認と、実機での表示・音・振動・明るさ・自動起動の確認は分けます。文書を更新するだけの場合はリンクやコマンド例を点検し、実機試験を実施していない項目を新たに確認済みと記載しません。
